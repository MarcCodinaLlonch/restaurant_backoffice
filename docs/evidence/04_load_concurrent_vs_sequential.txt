# Interpretació:
# - PostgreSQL: concurrent ~0,28 s  vs  seqüencial ~0,28 s
# - SQLite:     concurrent ~0,14 s  vs  seqüencial ~0,16 s
# - La BD és síncrona i les consultes van una darrere l'altra dins l'event loop:
#   per això el mode concurrent i el seqüencial donen temps semblants amb consultes ràpides.
# - El benefici de la concurrència apareix amb ESPERES DE XARXA (clients lents o inactius):
#   amb --idle-clients 3 els 30 clients acaben igualment en ~0,14 s sense bloquejar-se
#   (vegeu també 03_p1_vs_p2.txt).
